# Запуск бота, когда компьютер выключен

## Что уже размещено

Mini App работает на Sites. На отдельный постоянно работающий сервер переносится только
Python-процесс из telegram-bot: он принимает голосовые сообщения и отправляет напоминания.
Публикация исходников в GitHub сама по себе такой процесс не запускает.

## Вариант 1: Railway с исходниками GitHub

1. Войдите на https://railway.com/ и откройте New Project → Deploy from GitHub repo.
2. Выберите этот репозиторий. Корень проекта оставьте корнем репозитория; Dockerfile находится там.
3. В Variables добавьте четыре значения:

   | Переменная | Значение |
   |---|---|
   | TELEGRAM_BOT_TOKEN | Токен действующего Telegram-бота |
   | OPENAI_API_KEY | Ключ API OpenAI |
   | COLLEGE_APP_URL | https://digital-college-telegram-74926.dewylion4.chatgpt.site |
   | BOT_SERVICE_SECRET | Действующий серверный ключ Mini App |

4. Добавьте Volume и укажите точку монтирования `/data`. Dockerfile уже задаёт BOT_DATA_DIR=/data.
5. Оставьте одну реплику сервиса. Это фоновый worker, домен и HTTP-порт ему не нужны.
6. Отключите Serverless/App Sleeping, если этот параметр включён: бот должен постоянно опрашивать Telegram.
7. Остановите старую локальную копию бота. Только после этого запустите Redeploy серверной копии.
8. В логах дождитесь `College bot started`, отправьте `/app` и голосовое сообщение.
9. Убедитесь, что сообщения обрабатываются сервером, затем выключайте компьютер.

Railway может потребовать выбор тарифа, подтверждение аккаунта или оплату. Проверяйте условия
своего аккаунта. На 15 октября 2026 года на странице тарифов Hobby указан минимум $5 в месяц
с $5 включённого потребления; превышение ресурсов оплачивается отдельно. API OpenAI оплачивается
отдельно от хостинга: https://railway.com/pricing.

Данные вне Volume могут исчезнуть при следующем развёртывании. Источник:
https://docs.railway.com/services. В каталоге /data бот хранит SQLite с позицией чтения Telegram,
уточнениями и отметками об отправленных напоминаниях. Резервные копии этого каталога не публикуйте.

## Перенос текущей SQLite

Для сохранения незаконченных уточнений и состояния чтения остановите локального бота и
скопируйте `college.sqlite3` из его рабочего каталога data в `/data/college.sqlite3` на сервере.
Не копируйте её в исходники GitHub. Выполняйте перенос при остановленных обеих копиях.
Если начать с пустой базой, Telegram отдаст ещё ожидающие сообщения; уже подтверждённые Telegram
старые обновления не являются резервной копией истории.

## Вариант 2: свой VPS с Docker

На сервере установите Docker с Compose, скачайте репозиторий, создайте .env по примеру и выполните:

```bash
docker compose up -d --build
docker compose logs --tail=100 -f bot
```

После изменения кода: `git pull`, затем повторите `docker compose up -d --build`.
Для остановки: `docker compose stop bot`. Не добавляйте параметр удаления томов, если хотите
сохранить локальную SQLite. Перезапуск контейнера: `docker compose restart bot`.

## Серверные секреты Mini App

Уже настроены на Sites, в код их не помещать:

- TELEGRAM_BOT_TOKEN
- GOOGLE_SERVICE_ACCOUNT_JSON
- GOOGLE_SHEET_ID
- TEACHER_IDS
- BOT_SERVICE_SECRET

Хранилище и Mini App остаются на Sites, даже если Python-бот запущен на Railway или VPS.
Внешний сервер обращается к Mini App через HTTPS с BOT_SERVICE_SECRET.
